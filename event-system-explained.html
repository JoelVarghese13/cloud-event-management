The Big Picture: What Did We Build?

We built an entire university event management platform that lets students browse events, register, book tickets, and receive confirmation passes — backed by a rock-solid, multi-tier cloud infrastructure on Amazon Web Services (AWS).

👶 The "Amusement Park" Analogy (Explain Like I'm 5):
  • Custom VPC: A sturdy, fenced perimeter around our amusement park so outsiders cannot wander in.
  • EC2 Virtual Server (Node.js API): The friendly ticket counter at the front gate where visitors submit requests.
  • Amazon RDS (MySQL): The fireproof vault locked in the back office where all ticket counts and guest names live.
  • Amazon SQS: The orderly conveyor belt where ticket orders wait in line during huge rush hours without crashing.
  • AWS Lambda: The speedy robot worker that wakes up for 0.05 seconds, stamps each ticket, and goes back to sleep (saving all money!).
  • Amazon SNS: The homing pigeon that instantly delivers the confirmed ticket directly to the student's email inbox.

The 3-Person Team Breakdown (Rubric Alignment)

The architecture fulfills every university rubric requirement by dividing responsibilities cleanly into 3 specialized roles:

🛡️ Person A — Cloud Network & Security Lead Foundation & Security
  • Custom VPC (10.0.0.0/16): Created an isolated, private virtual network on AWS.
  • Public & Private Subnets: Placed EC2 in the public front yard and RDS in the private vault.
  • Internet Gateway (IGW): Connected the public subnet to the internet without paying for an expensive NAT Gateway (saving ~$32/month).
  • Security Groups: Configured allow-web for ports 22/80/3000, and allow-rds strictly locking port 3306 to EC2.
  • IAM Roles: Provisioned EventMgmtEC2Role and EventMgmtLambdaRole for keyless AWS SDK access.
  • AWS Budgets: Locked in a strict $2.00 spending cap with 50% & 80% email notifications.
⚙️ Person B — Core Backend & Database Admin Backend & Database
  • Amazon RDS (MySQL): Provisioned event-mgmt-db (db.t3.micro Free Tier) with 0-day backup retention to eliminate snapshot storage costs.
  • Database Schema (schema.sql): Engineered structured relational tables for users, events, and tickets.
  • SSM Parameter Store: Stored DB host, username, and encrypted password at /event-mgmt/db/*.
  • Amazon S3 (Flyer Storage): Created bucket event-mgmt-flyers-838775536247 with CORS enabled for flyer uploads.
  • Amazon SQS Queue: Created event-registration-queue for asynchronous decoupling.
  • Amazon EC2 Server: Launched Linux t3.micro instance at 3.109.144.78:3000 running Express via PM2.
💻 Person C — Frontend & Serverless Workflow Lead React & Serverless
  • AWS Lambda Worker (worker.py): Built Python 3.12 worker triggered by SQS in batches of 5 to process ticket passes.
  • Amazon SNS Topic (event-ticket-topic): Fans out ticket confirmations to attendees and team notifications.
  • React 18 Frontend: Created an interactive dark glassmorphic web app with 5 pages: Home, Browse Events, Ticket Reservation, My Tickets, and Organizer Dashboard.
  • CloudWatch Monitoring: Deployed EventMgmtDashboard and an automated high-CPU metric alarm.
